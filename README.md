# 🎃 Halloween Party Mini App

Telegram Mini App для Хэллоуин-вечеринки: гость нажимает **«ВЫРВИ ГЛАЗ»**, проходит
жуткая анимация, и ему выпадает одна из четырёх команд:

| Команда | Эмодзи | Цвет |
| --- | --- | --- |
| Зомби | 🧟 | зелёный |
| Вампиры | 🧛 | кроваво-красный |
| Привидения | 👻 | призрачно-голубой |
| Оборотни | 🐺 | лунно-янтарный |

Команды фиксируются в аккаунте Telegram: повторный вход показывает ту же команду.
Есть простая админка со списком гостей, счётчиками и экспортом в CSV.

Стек: **Node.js без единой зависимости** (только встроенные модули) + ванильный
фронтенд. Ничего ставить не нужно — `node server.js` и всё работает.
Прод-версия развёрнута как **Cloudflare Worker + D1** (файлы в `worker/`).

## 🌐 Прод: Cloudflare Worker + D1

Постоянный адрес (без туннелей и смены URL):

**https://halloween-miniapp.slava-halloween-2026.workers.dev**

Важно: в РФ провайдеры блокируют `*.workers.dev` — на телефоне/ПК нужен VPN.
Через VPN страница и API открываются стабильно.

- Код: `worker/src/index.js`, схема: `worker/schema.sql`, конфиг: `worker/wrangler.toml`.
- База: D1 `halloween-miniapp` (ID в `wrangler.toml`).
- Секреты `BOT_TOKEN` и `ADMIN_TOKEN` задаются через `wrangler secret bulk`, в git не попадают.
- Фронтенд и API отдаёт один Worker, поэтому CORS и отдельный домен не нужны.
- Деплой: `npm run worker:deploy` (нужен Node 18+ и `wrangler login`).
- Схема на удалённой D1: `npm run worker:schema`.

GitHub Pages для этого приложения не используется: Pages умеет только статику,
а здесь нужен бэкенд (`/api`, D1, проверка Telegram initData).

## Как работает распределение

Правило «равных порций»: в каждом **раунде** четыре команды выпадают по одной —
случайно, но без повторов. Один раунд = 4 гостя = ровно один зомби, один вампир,
одно привидение и один оборотень. Когда пул опустел — он снова наполняется.

Пример:

```
Гость 1 → 🧟 Зомби        (в пуле осталось: вампиры, привидения, оборотни)
Гость 2 → 👻 Привидения   (осталось: вампиры, оборотни)
Гость 3 → 🐺 Оборотни     (осталось: вампиры)
Гость 4 → 🧛 Вампиры      (пул пуст)
Гость 5 → 🧛 Вампиры      ← новый раунд, снова 4 команды в пуле
...
```

Такой подход гарантирует, что после 40 гостей в каждой команде будет ровно по 10
человек, а разница внутри вечеринки не превысит одного человека.

- Команда закрепляется за Telegram ID навсегда (при повторном входе — та же).
- Ведущий может **начать новый раунд** досрочно (кнопка в админке) — например,
  если пришла нечётная группа и остаток пула нужно обнулить.
- Все данные лежат в `data/db.json` — можно сделать бэкап простым копированием.

## Быстрый старт (локально)

```bash
node server.js
```

- Мини-апп: http://localhost:3000/
- Админка:  http://localhost:3000/admin?token=... (токен из `.env`)

Всё состояние хранится в `data/db.json`: команды гостей, остаток пула и номер
раунда. Файл переживает перезапуск сервера: можно закрыть терминал, перезагрузить
ноутбук и запустить снова — гости останутся в своих командах, а жеребьёвка
продолжится с того же места. При каждом запуске сервер делает резервную копию
в `data/backups/` (хранятся последние 12).

Проверить интерфейс в обычном браузере без Telegram можно, временно включив
`DEV_MODE=1` в `.env`: вход без Telegram тогда разрешён **только с этого же
компьютера** (localhost). При `DEV_MODE=0` мини-апп работает исключительно внутри
Telegram, а `x-dev-user` и запросы без подписи отклоняются.

Чтобы посмотреть распределение глазами разных гостей, открывай ссылки с параметром
`?as=имя` (значение хранится в `sessionStorage`, поэтому в разных вкладках можно
эмулировать разных людей):

```
http://localhost:3000/?as=alice
http://localhost:3000/?as=bob
http://localhost:3000/?as=carol
http://localhost:3000/?as=dave
http://localhost:3000/?as=eve
```

## Подключение к Telegram

1. Создай бота у [@BotFather](https://t.me/BotFather): `/newbot` → получишь токен.
2. Вставь токен в `.env`:
   ```env
   BOT_TOKEN=123456789:AA...
   ADMIN_TOKEN=придумай-длинную-случайную-строку
   PUBLIC_URL=https://твой-домен
   ```
3. Задеплой сервер на HTTPS-домен (Telegram Mini Apps работают только по HTTPS).
4. Привяжи мини-апп к боту. В BotFather:
   - `/newapp` — создать Mini App и указать HTTPS-URL;
   - либо `/setmenubutton` — кнопка меню слева от поля ввода;
   - либо отправь гостям прямую ссылку `https://t.me/имя_бота/имя_аппа`.

Мини-апп можно открывать и как обычную ссылку из чата — главное, чтобы она вела
на HTTPS-страницу с подключённым `telegram-web-app.js`.

### Мини-апп на ноутбуке (HTTPS-туннель)

Telegram открывает Mini App только по HTTPS, поэтому ноутбуку нужен туннель.

```powershell
# терминал 1 — сервер
npm start

# терминал 2 — туннель (при первом запуске сам скачает cloudflared)
powershell -ExecutionPolicy Bypass -File tools\tunnel.ps1
```

В консоли туннеля появится адрес вида `https://random-words-1234.trycloudflare.com`.

1. Вставь этот адрес в BotFather: `/newapp` (создать Mini App) или
   `/setmenubutton` (кнопка меню в чате с ботом).
2. При желании продублируй его в `.env` → `PUBLIC_URL=` (нужен для кнопки
   «Позвать своих»; без него берётся адрес из браузера).
3. Отправь гостям ссылку `https://t.me/имя_бота/имя_аппа` — или попроси открыть
   чат с ботом и нажать кнопку меню.

Окно туннеля должно оставаться открытым всю вечеринку. Адрес живёт, пока запущен
`cloudflared`; после его перезапуска адрес изменится — тогда обнови URL в BotFather.
Сам сервер можно перезапускать сколько угодно: гости, команды и раунд сохранятся.

Если туннель ругается на QUIC или отдаёт ошибку 530, попробуй убрать
`--protocol http2` из `tools/tunnel.ps1` (или наоборот добавить `--protocol quic`).
Запасной вариант — [ngrok](https://ngrok.com): `ngrok http 3000`.

### Боевой сервер (пример для VPS)

```bash
# Node 16+ уже должен быть установлен
git clone ... # или просто скопируй папку проекта
cd halloween
cp .env.example .env
nano .env            # BOT_TOKEN, ADMIN_TOKEN, PUBLIC_URL
node server.js       # проверка
```

systemd-юнит `/etc/systemd/system/halloween.service`:

```ini
[Unit]
Description=Halloween Mini App
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/halloween
ExecStart=/usr/bin/node /opt/halloween/server.js
Restart=always
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now halloween
```

Дальше — nginx/Caddy с HTTPS-сертификатом (Caddy справится сам) и проксированием
на `127.0.0.1:3000`.

Для nginx не забудь передать реальный IP гостя и включить `TRUST_PROXY=1`:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен бота. Пусто → демо-режим |
| `ADMIN_TOKEN` | — | Ключ для `/admin`. Пусто + прод → админка закрыта |
| `PUBLIC_URL` | — | HTTPS-адрес для кнопки «Позвать своих» |
| `BOT_USERNAME` | — | Username бота без `@` — «Позвать своих» отправляет ссылку `https://t.me/<username>` |
| `PORT` | `3000` | Порт |
| `HOST` | `0.0.0.0` | Интерфейс |
| `MAX_INIT_AGE` | `86400` | Срок жизни `initData`, сек (0 — не проверять) |
| `TRUST_PROXY` | `0` | `1` — брать реальный IP из `X-Forwarded-For` (за nginx/Caddy/туннелем) |
| `DEV_MODE` | авто | `1` — вход без Telegram (с localhost, если задан `BOT_TOKEN`); `0` — только Telegram |
| `DATA_DIR` | `./data` | Каталог хранилища |
| `EXPORT_DIR` | `./exports` | Куда `npm run export` пишет файлы |
| `PARTY_TITLE` | — | Резерв под название вечеринки |

## Админка

`https://твой-домен/admin` → введи `ADMIN_TOKEN` (сохраняется в `sessionStorage`)
или открой `/admin?token=...`.

Что умеет:

- кнопка **«Список команд»** в мини-аппе — доступна всем гостям, прошедшим
  Telegram-авторизацию (обновляется автоматически);
- живой список гостей по командам (обновление каждые 5 секунд);
- счётчики: всего гостей, номер раунда, сколько распределено в текущем раунде,
  сколько команд осталось в пуле;
- **Новый раунд** — обнуляет остаток пула (следующие 4 гостя снова получат по одной
  команде);
- **Сбросить всё** — удаляет участников и историю (только до начала вечеринки);
- **CSV** — выгрузка с BOM для Excel: №, имя, username, Telegram ID, команда,
  раунд, время.

## Выгрузка списка команд (без браузера)

```bash
npm run status   # показать список в консоли
npm run export   # создать exports/teams-<дата>.csv и .md
npm run reset    # очистить базу перед новой вечеринкой (спросит подтверждение)
```

`export` пишет два файла: `.csv` (открыть в Excel / Google Таблицах) и `.md`
(готовый текст, который удобно скинуть в чат). Старые версии базы лежат в
`data/backups/`, так что случайный сброс можно откатить копированием файла.

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| `GET` | `/api/config` | Команды, количество гостей, режим |
| `GET` | `/api/me` | Команда текущего гостя (или `null`) |
| `POST` | `/api/join` | Выдать/вернуть команду (идемпотентно) |
| `GET` | `/api/admin/stats` | Полная статистика (нужен `x-admin-token`) |
| `GET` | `/api/teams` | Список команд для любого гостя с Telegram `initData` (алиас: `/api/host/teams`) |
| `POST` | `/api/admin/reset-round` | Новый раунд |
| `POST` | `/api/admin/reset-all` | Полный сброс |
| `GET` | `/api/admin/export.csv` | CSV-выгрузка |
| `GET` | `/health` | Проверка живости |

Авторизация гостя: заголовок `x-telegram-init-data` с `Telegram.WebApp.initData`.
Сервер проверяет подпись по алгоритму Telegram (`HMAC-SHA256(WebAppData, bot_token)`)
и срок жизни `auth_date`.

## Что происходит на экране гостя

1. **Интро**: зрачок следит за пальцем/курсором, кнопка «ВЫРВИ ГЛАЗ» пульсирует.
2. **Жребий**: экран трясётся, звучит свист и низкий гул (звук включён по умолчанию,
   отключается кнопкой 🔇 в правом верхнем углу), кольцо с четырьмя символами
   раскручивается и замедляется, указатель останавливается на выпавшей команде.
3. **Результат**: вспышка, разлёт частиц, карточка команды переворачивается,
   показывает название, девиз, «фишку» команды и число гостей в ней. У каждой
   команды свой звук: вой оборотня, «буу» привидения, стон зомби и вампирский стинг.
4. **Повторный вход**: сразу карточка с той же командой и пометкой
   «Команда уже закреплена за тобой».

Все анимации отключаются при `prefers-reduced-motion: reduce`, звук выключен по
умолчанию и включается кнопкой в правом верхнем углу.

## Мелочи, которые стоит знать

- **Один Telegram-аккаунт = одна команда навсегда.** Это by design: подделать
  нельзя без валидного `initData`.
- **Данные гостей**: имя, username, Telegram ID, время. Ничего лишнего.
  `db.json` не отдаётся наружу (лежит вне `public/`).
- **Фото профиля** сохраняется в базе (URL), но в админке не показывается.
- **Сброс пула vs сброс всего**: «Новый раунд» не трогает команды гостей,
  «Сбросить всё» — стирает всех.
- **Бэкап**: скопируй `data/db.json`. При каждом запуске сервера и перед сбросом
  копия автоматически кладётся в `data/backups/`. Для переноса на другой сервер
  достаточно папки проекта + `db.json`.
- **Ограничение запросов**: не больше 240 бросков жребия в минуту с одного IP —
  защита от случайной «долбёжки» кнопкой. За прокси включи `TRUST_PROXY=1`,
  иначе все гости будут выглядеть как один IP.
- **Если поменял BOT_TOKEN**, старые `initData` перестанут проходить проверку —
  это нормально, гости просто переоткроют приложение.

```bash
node server.js
```

```powershell
1..12 | ForEach-Object {
  $r = Invoke-RestMethod -Uri http://localhost:3000/api/join -Method Post `
       -Headers @{ 'x-dev-user' = "test$_" }
  "{0,2}  {1}" -f $_, $r.participant.team
```
